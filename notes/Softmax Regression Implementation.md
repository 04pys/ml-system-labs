# 소프트맥스 회귀 구현 복습 트리거


## 1. 가장 핵심 그림
소프트맥스 회귀에서 모델이 하는 일은 결국 이것 하나임

- z = xW + b
- z의 shape = (샘플 수, 클래스 수)
- 각 샘플마다 클래스별 점수(logit) 3개가 나옴
- 이 3개 점수에 softmax를 적용하면 각 클래스 확률이 됨

즉 이 예제에서는

- 입력 4개 -> 출력 3개
- 그래서 `W`의 shape은 (4, 3)
- `b`의 shape은 (1, 3)
- `nn.Linear(4, 3)`과 정확히 대응됨

---

## 2. 왜 nn.Module에서 output_dim이 1이 아니냐
이 부분이 제일 자주 헷갈리는 포인트임

### 선형 회귀 / 이진 로지스틱 회귀
- 출력이 하나면 됨
- 이유:
  - 선형 회귀: 숫자 1개 예측
  - 이진 로지스틱 회귀: 한 샘플이 1일 확률 하나만 알면 됨
- 그래서 보통 output_dim = 1

### 소프트맥스 회귀
- 클래스가 여러 개이면 **클래스마다 점수 1개씩** 필요함
- 이 예제는 클래스가 3개이므로 출력이 3개여야 함
- 그래서 `nn.Linear(4, 3)`이 맞음

정리하면

- 이진 분류면 출력 1개
- 다중 클래스 분류면 출력 = 클래스 개수

---

## 3. 로우레벨과 하이레벨은 무엇이 다른가
수학은 같고, **직접 쓰느냐 / PyTorch 함수에 맡기느냐** 차이임

### 1) 로우레벨
직접 다 씀

- `hypothesis = softmax(z)`
- `y`를 one-hot으로 만듦
- `cost = -(y_one_hot * log(hypothesis)).sum(...).mean()`

즉, softmax와 cross entropy를 사람이 손으로 풀어서 구현한 버전임

### 2) 하이레벨
핵심 계산을 함수에 맡김

- `z = x_train.matmul(W) + b`
- `cost = F.cross_entropy(z, y_train)`

여기서 중요한 점:

- `F.cross_entropy`는 **logits z**를 입력으로 받음
- 내부에서 softmax + log + NLL 계산을 처리함
- 그래서 **직접 softmax를 먼저 하면 안 됨**

즉, 로우레벨에서 손으로 하던 것을 하이레벨에서는 한 함수에 맡긴 것임

---

## 4. nn.Module 구현은 무엇이 추가된 것인가
`W`, `b`를 직접 만들지 않고, 모델 객체가 대신 관리하게 한 것뿐임

로우/하이레벨에서는 직접

- `W`
- `b`

를 만들었음

nn.Module에서는

- `model = nn.Linear(4, 3)`

이 한 줄이 내부적으로 가중치와 편향을 관리함

즉

- `x.matmul(W) + b`
- 와
- `model(x)`

는 같은 역할이라고 보면 됨

---

## 5. 클래스로 구현하는 것은 또 뭐가 다른가
사실 본질은 안 달라짐

`nn.Linear(4, 3)`를 그냥 바로 쓰는 대신,
그걸 내가 정의한 클래스 안에 넣어두는 것임

예:

- `self.linear = nn.Linear(4, 3)`
- `forward`에서 `return self.linear(x)`

즉 클래스 버전은

- 모델 구조를 더 명확하게 관리하려고
- `nn.Module`을 상속해서 감싼 버전일 뿐임

수학적으로는 여전히

- z = xW + b

와 같음

---

## 6. 연결해서 보면 이렇게 됨
### 로우레벨
- 내가 직접 softmax도 쓰고
- one-hot도 만들고
- log, sum, mean도 직접 계산함

### 하이레벨
- `F.cross_entropy`가 그 과정을 대신 해줌
- 대신 입력은 확률이 아니라 **logits**여야 함

### nn.Module
- `W`, `b`를 직접 안 만들고
- `nn.Linear`가 파라미터를 관리함

### 클래스 구현
- `nn.Linear`를 내가 만든 클래스 안에 넣어서
- 구조를 더 깔끔하게 정리한 버전임

즉,

- 로우레벨: 계산을 직접 펼쳐서 이해하는 단계
- 하이레벨: 계산을 함수로 축약한 단계
- nn.Module / 클래스: 파라미터 관리와 구조화를 더 편하게 만든 단계

---

## 7. 제일 중요한 실수 방지 포인트
### 실수 1
`nn.Linear(4, 3)`인데 왜 출력이 3이냐?

- 클래스가 3개라서
- 각 클래스 점수(logit)가 하나씩 필요해서

### 실수 2
`forward`에서 softmax를 또 붙여야 하나?

- 학습 때 `F.cross_entropy`를 쓰면 **붙이지 않음**
- 이유: `F.cross_entropy` 안에 softmax 관련 계산이 이미 들어 있음

### 실수 3
이전 선형 회귀나 이진 로지스틱 회귀처럼 output_dim을 1로 두면 되나?

- 안 됨
- 이 예제는 다중 클래스 분류라서 output_dim은 클래스 수와 같아야 함

---

## 8. 한 줄 요약
소프트맥스 회귀에서는

- 입력 4개 -> 클래스 3개면 출력 3개
- 로우레벨은 softmax + cross entropy를 직접 구현
- 하이레벨은 `F.cross_entropy`가 대신 처리
- `nn.Module`과 클래스 구현은 같은 모델을 더 편하게 관리하는 방식

---

## 9. 머릿속 암기 문장
- **다중 클래스 분류의 출력 차원은 클래스 개수와 같음**
- **`F.cross_entropy`를 쓰면 softmax를 따로 쓰지 않음**
- **`model(x)`는 결국 `xW + b`를 더 편하게 쓴 것임**
- **로우레벨, 하이레벨, nn.Module, 클래스 구현은 수학은 같고 표현만 다름**
